# 웹 디자인 스킬

목표: 사람이 의도를 갖고 만든 것처럼 보이는 페이지. "깔끔하지만 어디서 본 것 같은" 결과물은 실패로 본다.

## 1. 만들기 전에: 방향 한 줄 정하기

코드를 쓰기 전에 아래 세 가지를 한 줄씩 정하고, 사용자에게 짧게 알린다. 사용자가 레퍼런스(좋아하는 사이트)나 톤을 줬다면 그걸 우선한다.

- **톤**: 하나만 고른다. 예) 시험 대비 노트처럼 / 신문·잡지처럼 / 개발 문서처럼 / 레트로 단말기처럼 / 손글씨 플래너처럼 / 차분한 도구처럼
- **기억에 남을 요소 1개**: 이 페이지만의 특징. 예) 큰 숫자 타이포, 형광펜 밑줄, 모눈종이 배경, 티켓 모양 카드, 진행도를 보여주는 가로 타임라인
- **주 사용 상황**: 폰에서 잠깐 보는지, 책상에서 오래 보는지 → 밀도와 글자 크기가 달라진다

"모던하고 깔끔하게"는 방향이 아니다. 아무것도 정하지 않은 것과 같다.

## 2. 금지 패턴 (AI 티의 주범)

다음은 기본적으로 쓰지 않는다. 쓰려면 위에서 정한 톤에 맞는 분명한 이유가 있어야 한다.

- 보라·파랑 그라데이션 헤더, 그라데이션 텍스트, 글로우·네온 효과
- 화면 가운데 큰 제목 + 부제 + 버튼 2개로 시작하는 히어로
- 똑같은 크기의 카드 3개(또는 4개)가 나란히 있는 그리드, 각 카드 위에 아이콘 하나
- 모든 요소에 `border-radius: 16px` + `box-shadow` 를 똑같이 적용
- 이모지를 아이콘 대용으로 사용 (🚀 ✨ 📚 💡 🎯 등), 제목 앞 이모지
- "시작하기", "더 알아보기", "당신의 ○○을 한 단계 업그레이드" 같은 마케팅 문구
- 의미 없는 장식 블롭(흐릿한 원), 파티클, 유리(glassmorphism) 카드
- 회색 배경(#f5f7fb 류) 위에 흰 카드만 반복되는 구성
- 모든 섹션이 같은 폭·같은 여백·같은 정렬
- `Segoe UI, Arial` 같은 기본 폰트만 쓰는 것, 또는 아무 생각 없이 Inter만 쓰는 것
- hover 시 무조건 `translateY(-4px)` 로 떠오르는 효과

## 3. 대신 이렇게

### 타이포그래피가 디자인의 절반
- 제목용 폰트와 본문용 폰트를 구분한다. 크기 대비를 크게 준다(제목은 본문의 2.5~4배도 괜찮다).
- 한글 추천 조합 (모두 무료·오픈 라이선스):
  - 본문: Pretendard, IBM Plex Sans KR, Noto Sans KR, SUIT
  - 제목/포인트: Noto Serif KR, Gowun Batang, Gowun Dodum, Black Han Sans, Do Hyeon, Nanum Myeongjo
  - 숫자·코드: IBM Plex Mono, JetBrains Mono, Martian Mono
- 행간 1.6~1.75(한글), 본문 한 줄 최대 약 40자(한글 기준 `max-width: 34em` 내외).
- 숫자는 `font-variant-numeric: tabular-nums` 로 정렬.

### 색
- 색은 `:root` 에 토큰으로 정의한다: 배경, 표면, 글자, 흐린 글자, 선, 강조색 1개(+필요하면 보조 1개).
- 강조색은 아껴 쓴다. 화면의 5~10% 정도. 나머지는 중립색.
- 순수 흰색·순수 검정 대신 약간 따뜻하거나 차가운 톤(예: `#fbfaf7`, `#1d1c1a`).
- 다크 모드는 `prefers-color-scheme` 로 토큰만 바꿔서 지원한다.

### 레이아웃
- 정보의 중요도에 따라 크기를 다르게 한다. 모든 카드를 같은 크기로 만들지 않는다.
- 카드 대신 선(border-top, 구분선), 여백, 표, 목록으로 묶는 걸 먼저 고려한다.
- 왼쪽 정렬을 기본으로. 가운데 정렬은 짧은 문구에만.
- 모바일 우선: 좌우 여백 16px, 가로 스크롤 없음, 터치 영역 최소 44px.

### 아이콘·이미지
- 아이콘이 필요하면 Lucide, Tabler, Phosphor 중 하나를 골라 일관되게 쓴다(MIT/ISC 라이선스). 인라인 SVG로 넣는 게 가장 안전하다.
- 아이콘이 꼭 필요하지 않으면 쓰지 않는다. 텍스트 라벨이 더 명확한 경우가 많다.
- 이미지는 저장소에 넣은 파일만 사용한다. 외부 이미지 핫링크 금지.

### 문구
- 기능을 그대로 말한다. "오늘 풀 문제 12개", "다음 시험까지 D-34" 처럼 구체적인 숫자와 사실.
- 버튼 라벨은 동작을 쓴다: "문제 풀기", "오답만 다시 보기".

## 4. 보안·의존성 규칙

- 외부 스크립트는 `cdnjs.cloudflare.com` 또는 `cdn.jsdelivr.net/npm/` 에서만, **정확한 버전을 고정**해서 불러온다. (예: `d3/7.9.0`, `lucide@0.469.0`) `@latest` 나 버전 없는 URL 금지.
- 폰트는 Google Fonts 또는 jsdelivr(Pretendard 등)에서만.
- 가능하면 외부 스크립트 없이 순수 HTML/CSS/JS로 만든다. 라이브러리 하나를 위해 아이콘 몇 개를 가져오는 거라면 SVG를 직접 붙여넣는다.
- API 키, 토큰, 개인정보를 페이지 코드에 넣지 않는다.
- 사용자 입력을 화면에 다시 그릴 때는 `textContent` 를 쓰고 `innerHTML` 에 직접 넣지 않는다.
- `localStorage` 접근은 `try/catch` 로 감싼다.

## 5. 만든 뒤: 스크린샷으로 직접 확인 (필수)

이 환경에는 Chromium과 Playwright가 설치되어 있다. 만든 페이지는 반드시 찍어서 눈으로 확인한 뒤 고친다.

```bash
node .claude/skills/web-design/scripts/shot.js <html 파일 경로> [출력 폴더]
```

- 데스크톱(1280px), 모바일(390px) 두 장을 라이트·다크 모드로 찍는다(총 4장). 출력 폴더를 생략하면 스크래치패드나 `/tmp` 아래에 저장한다.
- 찍은 이미지를 Read 도구로 열어 보고 아래를 점검한다:
  1. 2장의 금지 패턴이 하나라도 보이는가?
  2. 3초 안에 이 페이지가 뭘 하는 곳인지 알 수 있는가?
  3. 1단계에서 정한 "기억에 남을 요소"가 실제로 눈에 띄는가?
  4. 모바일에서 글자가 잘리거나 가로 스크롤이 생기는가?
  5. 다크 모드에서 안 보이는 글자·선이 있는가?
- 문제가 있으면 고치고 다시 찍는다. 최소 1회는 수정-재확인을 거친다.

## 6. 기존 페이지를 고칠 때

- 먼저 현재 페이지를 스크린샷으로 찍어서 무엇이 AI 티를 내는지 2장 기준으로 짚는다.
- 기능(JS 로직, 데이터)은 건드리지 않고 스타일과 마크업 구조만 바꾸는 것을 기본으로 한다.
- 바꾸기 전/후 스크린샷을 둘 다 남겨 사용자에게 비교해서 보여준다.
