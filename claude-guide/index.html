01

클로드 vs 클로드 코드

같은 AI 모델이 들어 있지만, 일하는 방식이 다릅니다. 하나는 대화로 돕고, 다른 하나는 파일과 컴퓨터를 직접 만집니다.

클로드 Claude · claude.ai 앱

말로 돕는 똑똑한 동료. 질문하면 답하고, 글을 쓰고, 파일을 읽고 분석합니다.

  • 웹(claude.ai), 데스크톱 앱, 모바일 앱
  • 문서 요약, 기획안, 이메일 초안, 데이터 분석
  • 아티팩트로 문서·페이지·간단한 앱 만들기
  • 커넥터로 구글 드라이브, Gmail 등과 연결
클로드 코드 Claude Code

키보드를 맡겨둔 동료. 폴더 안의 파일을 직접 열고 고치고, 명령을 실행하고, 결과를 저장합니다.

  • 터미널(CLI), 데스크톱 앱, 웹(claude.ai/code), VS Code·JetBrains
  • 웹페이지·자동화 스크립트 만들기, 버그 고치기
  • 깃허브에 저장(커밋)하고 검토 요청(PR)까지
  • 클라우드에서 돌려두고 휴대폰으로 확인 가능
구분클로드 (claude.ai)클로드 코드
작업 대상대화창에 올린 파일, 커넥터로 연결한 서비스내 컴퓨터 폴더 또는 깃허브 저장소 전체
하는 일읽고, 생각하고, 써서 보여줌읽고, 고치고, 실행하고, 저장까지 함

기억/규칙개인 선호(지침), 스타일, 프로젝트 지침, 메모리CLAUDE.md, settings.json, 권한 설정

쉽게 말하면

클로드는 답을 알려주는 동료, 클로드 코드는 직접 해주는 동료입니다. 결과물이 "읽을거리"면 클로드, "파일·웹페이지·자동화"면 클로드 코드를 먼저 떠올리세요. 둘은 같은 계정으로 쓰고, 같은 모델을 공유합니다.

03

기본 개인 설정: 규칙과 지침

매번 "한국어로, 결론부터, 표로" 같은 말을 반복하지 않도록 한 번 적어두는 규칙입니다. 클로드와 클로드 코드는 적어두는 위치가 다릅니다.

쉽게 말하면

새로 온 팀원에게 주는 업무 인수인계 메모라고 생각하세요. 클로드는 대화를 시작할 때마다 이 메모를 먼저 읽고 일을 시작합니다. 메모가 구체적일수록 결과가 우리 팀 스타일에 가까워집니다.

A. 클로드(claude.ai)에서 설정하기

개인 선호(지침) 적기 설정 → 프로필(개인 선호) 입력란 · 모든 대화에 적용

나에 대한 정보와 답변 방식을 적습니다. 아래 예시를 복사해서 내 상황에 맞게 고치세요.

- 항상 한국어로 답해줘. 전문 용어는 처음 나올 때 한 줄로 풀어줘.
- 결론을 먼저 말하고, 근거는 그 다음에 짧게.
- 나는 ○○팀에서 △△ 업무를 해. 예시는 이 업무 기준으로 들어줘.
- 확실하지 않으면 추측이라고 표시하고, 모르면 모른다고 말해줘.
- 표는 엑셀/구글 시트에 바로 붙여넣을 수 있게 만들어줘.
스타일 고르기 입력창의 스타일 메뉴

간결하게, 설명 위주로, 격식 있게 등 말투를 고릅니다. 내 글 샘플을 올려 나만의 스타일을 만들 수도 있습니다.

프로젝트 만들고 프로젝트 지침 넣기 왼쪽 메뉴 → 프로젝트 → 새 프로젝트

업무별 전용 방입니다. 자주 참고하는 자료(브랜드 가이드, 지난 보고서)를 올리고, 이 프로젝트에서만 지킬 규칙을 적습니다. 팀원과 공유할 수도 있습니다.

이 프로젝트는 주간 마케팅 리포트 작성용이야.
- 첨부한 '리포트_양식.docx' 구조를 그대로 따라줘.
- 수치는 반드시 출처 파일명과 함께 적어줘.
- 문체는 존댓말, 한 문장은 50자 이내.
메모리와 커넥터 확인 설정 → 기능(메모리) / 설정 → 커넥터

메모리를 켜면 지난 대화의 맥락을 기억합니다. 커넥터로 구글 드라이브·Gmail·캘린더 등을 연결하면 클로드가 그 안의 자료를 직접 찾아 읽습니다. 회사 보안 정책에 맞는 것만 연결하세요.

B. 클로드 코드에서 설정하기

CLAUDE.md — 작업 규칙 메모

폴더 안에 두는 텍스트 파일입니다. 클로드 코드가 작업을 시작할 때 자동으로 읽습니다. 처음엔 /init 명령을 치면 클로드가 폴더를 훑어보고 초안을 만들어 줍니다.

위치적용 범위
~/.claude/CLAUDE.md내 컴퓨터의 모든 프로젝트 (나만의 습관)
프로젝트폴더/CLAUDE.md이 저장소만. 깃허브에 올려 팀 공유
 
# 프로젝트 규칙 (CLAUDE.md 예시)

## 목적
팀 내부용 웹 도구 모음. 깃허브 페이지로 배포.

## 규칙
- 페이지는 HTML 파일 하나로, 서버 없이 동작하게
- 화면 문구는 한국어 존댓말
- main 브랜치에 바로 올리지 말고 PR로
- 데이터 저장은 Firebase(firebase-config.js)만 사용
- 비밀번호·API 키는 절대 커밋하지 않기

## 확인 방법
- 수정 후 휴대폰 폭(400px)에서도 깨지지 않는지 확인
팀 규칙은 짧고 구체적으로. "잘 해줘"보다 "PR로 올려줘"가 효과적입니다.
settings.json — 권한(허락) 설정

클로드 코드는 파일을 고치거나 명령을 실행하기 전에 허락을 구합니다. 매번 묻지 않아도 되는 안전한 작업은 허용, 절대 보면 안 되는 파일은 거부로 적어둡니다. /permissions 명령으로 화면에서 바꿀 수도 있습니다.

위치: ~/.claude/settings.json(나) · .claude/settings.json(팀 공유) 
{
  "permissions": {
    "allow": [
      "Bash(git status)",
      "Bash(git diff:*)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)"
    ]
  }
}
처음 설정할 때 주의
  • 지침은 길다고 좋은 게 아닙니다. 10줄 안쪽의 구체적 규칙이 가장 잘 지켜집니다.
  • 개인정보·고객 데이터·사내 기밀은 회사 정책을 먼저 확인하고 올리세요.
  • 지침이 서로 충돌하면(예: "짧게" + "자세히") 결과가 흔들립니다. 우선순위를 적어주세요.
04

깃허브(GitHub)란?

코드와 파일을 버전 기록과 함께 보관하고, 여러 사람이 안전하게 같이 고치도록 돕는 온라인 저장소입니다.

쉽게 말하면

구글 드라이브 + 무제한 되돌리기 + 결재 시스템입니다. 누가 언제 무엇을 왜 바꿨는지 전부 남고, 바꾼 내용은 "검토 요청 → 승인 → 반영" 순서를 거칩니다. 클로드 코드는 이 과정을 대신 처리해 줍니다.

저장소프로젝트 폴더 한 개repo
브랜치원본을 건드리지 않는 작업용 사본branch
커밋"여기까지 저장" 기록 한 줄commit
푸시내 컴퓨터 → 깃허브로 올리기push
PR"이거 반영해도 될까요?" 검토 요청pull request
머지승인 후 원본(main)에 합치기merge

우리 팀 예시. 지금 이 교육 자료가 들어 있는 저장소에는 level-up(습관 앱), budget, travel-map 같은 페이지들이 폴더별로 들어 있습니다. 클로드 코드에 "레벨업 앱에 이어하기 기능 넣어줘"라고 하면, 클로드가 브랜치를 만들고 → 파일을 고치고 → 커밋하고 → PR을 올립니다. 우리는 PR에서 바뀐 내용을 확인하고 머지 버튼만 누르면 됩니다.

깃허브 페이지(GitHub Pages)를 켜 두면 main에 머지된 HTML 파일이 곧바로 인터넷 주소로 열립니다. 별도 서버 없이 무료로 웹페이지를 띄우는 가장 쉬운 방법입니다.

깃허브를 처음 쓴다면: 계정부터 클로드 연결까지
  • 계정 만들기 github.com 가입 → 팀 관리자에게 아이디를 알려 조직/저장소 초대 받기
  • 클로드와 연결 claude.ai/code 접속 → 깃허브 연결 → Claude GitHub 앱을 저장소에 설치(권한 허용)
  • 저장소 선택 새 세션에서 작업할 저장소를 고르면, 클라우드에 그 저장소가 복사된 상태로 클로드가 일을 시작합니다
  • 결과 확인 클로드가 올린 PR 링크를 눌러 "Files changed" 탭에서 바뀐 부분을 확인 → Merge
05

상시 운영을 위한 서버와 데이터베이스

"내 컴퓨터를 꺼도 계속 돌아가게" 하려면 무엇이 필요할까요? 하고 싶은 일에 따라 필요한 것이 다릅니다. 대부분은 서버를 직접 운영할 필요가 없습니다.

쉽게 말하면

서버는 24시간 켜져 있는 남의 컴퓨터, 데이터베이스는 그 컴퓨터 안의 공용 엑셀 파일입니다. 웹페이지만 보여주면 되는 경우는 깃허브 페이지로 충분하고, 여러 사람이 입력한 내용을 저장·공유해야 할 때 구글의 데이터베이스(Firebase)를 붙입니다.

화면사용자 브라우저

휴대폰·PC에서 주소를 열면 HTML 페이지가 보입니다.

페이지 호스팅깃허브 페이지

저장소의 HTML을 인터넷 주소로 무료 공개. 서버 관리 없음.

데이터 저장Firebase · Firestore

구글의 클라우드 데이터베이스. 기록·점수·설정을 저장하고 기기 간 동기화.

실제 예: level-up 앱은 깃허브 페이지에서 열리고, firebase-config.js로 Firestore에 연결해 아이폰과 PC 사이에 진행 상황을 동기화합니다.

하고 싶은 일추천 도구비용 감클로드에게 이렇게
웹페이지를 항상 열려 있게깃허브 페이지무료"이 HTML을 깃허브 페이지로 배포되게 저장소에 올려줘"
사람들이 입력한 데이터를 저장·공유Firebase Firestore (구글)소규모는 무료 구간"기록을 Firestore에 저장하고 로그인한 사람만 보게 해줘"
표 형태의 간단한 데이터구글 시트 + Apps Script무료"폼 응답을 구글 시트에 쌓는 스크립트 만들어줘"
정해진 시간마다 코드 실행GitHub Actions(예약 실행) 또는 Google Cloud Run + Scheduler무료 구간 / 사용량 과금"매일 아침 9시에 환율 가져와서 파일 갱신하는 작업 만들어줘"
정해진 시간마다 클로드가 일하게클로드 코드 예약 작업(클라우드 세션)클로드 요금제 사용량"매주 월요일 저장소 변경사항 요약해서 알려줘"
계속 켜져 있는 백엔드 서버Google Cloud Run 등사용량 과금처음엔 위 방법들로 해결되는지 먼저 확인
운영 시 꼭 지킬 것
  • 비밀 키는 저장소에 올리지 않기. API 키·비밀번호는 환경 변수나 시크릿 설정에 둡니다. 깃허브에 한 번 올라가면 지워도 기록에 남습니다.
  • Firebase 보안 규칙(Security Rules) 설정. 웹용 Firebase 설정값은 공개돼도 되지만, 규칙이 열려 있으면 누구나 데이터를 읽고 지울 수 있습니다.
  • 결제 알림 켜기. 구글 클라우드는 예산 알림을 걸어두면 예상치 못한 과금을 막을 수 있습니다.

함께 해보기 (20분)

오늘 배운 순서 그대로 한 바퀴 돌아봅니다.

클로드에 개인 선호 넣기

03-A의 예시를 복사해 내 업무에 맞게 고친 뒤 저장 → 새 대화에서 "자기소개 한 줄 써줘"로 반영됐는지 확인.

프로젝트 하나 만들기

내 업무 하나를 골라 프로젝트를 만들고, 참고 파일 1개와 프로젝트 지침 3줄을 넣어봅니다.

클로드 코드(웹)에서 저장소 열기

claude.ai/code → 팀 저장소 선택 → 아래 요청을 그대로 입력합니다.

내 이름으로 된 자기소개 페이지를 me/내이름.html 로 만들어줘.
- 휴대폰에서도 보기 좋게
- 한국어, 3문단 이내
- 다 만들면 PR로 올려줘
PR 확인하고 머지

클로드가 준 PR 링크 → 바뀐 파일 확인 → 이상 없으면 Merge. 잠시 후 깃허브 페이지 주소에서 내 페이지가 열리는지 확인합니다.

실전 과제: 우리 팀에 진짜 필요한 앱 두 개

2~3명이 한 조가 되어 둘 중 하나를 고르세요. 어떤 기능이 필요한지는 조에서 직접 정하고, 코드는 쓰지 않고 클로드 코드에게 설명만 합니다.

공통 조건
  • 팀 저장소에 폴더 하나로: 아침묵상은 devotion/, 점심은 lunch/
  • 팀원 모두가 같은 기록을 봐야 함 (기존 Firebase 사용)
  • PR로 올리고, 다른 조가 써본 뒤 머지
과제 A · 아침묵상 나눔 기록앱devotion/

매일 아침 매일성경 그날 본문으로 묵상하고 함께 나눕니다. 한 명씩 돌아가며 인도하고, 인도자가 마침기도까지 맡습니다. 가끔은 실장님과 함께 드리고, 안내와 나눔은 팀즈 단톡방에 올립니다.

도전 기능
  • 사람별 인도 횟수와 최근 인도일
  • 달력 보기: 나눈 날, 실장님과 함께한 날, 쉰 날을 색으로 구분
  • "며칠째 이어서 나누는 중" 연속 기록
  • 실장님과 함께한 날만 모아보기
과제 B · 점심 메뉴 순번·이력 앱lunch/

점심 메뉴 고르는 사람을 공평하게 돌아가며 정하고, 누가 언제 무엇을 골랐는지 남깁니다.

도전 기능
  • 최근 2주 안에 같은 메뉴를 고르면 "또 먹어요?" 경고
  • 식당 별점과 자주 간 식당 순위
  • 고민될 때 지난 이력에서 메뉴 랜덤 추천
막히면 열어보기: 기본 기능 예시 · 데이터 구조 · 진행 순서
아침묵상 기본 기능 예시
  • 오늘 인도자와 내일 인도자 표시
  • 인도 순번: 명단·순서, 건너뛰기, 바꾸기
  • 그날 본문 범위, 구절, 한 줄 나눔, 기도제목 기록
  • 실장님과 함께한 날 표시 (실장님이 인도하면 순번 유지)
  • 지난 기록 검색, 팀즈용 복사

매일성경 본문·해설은 저작권이 있으니 본문 범위와 우리 나눔만 기록합니다.

점심 기본 기능 예시
  • 오늘 고를 사람과 다음 차례 표시
  • 명단·순서, 건너뛰기, 바꾸기
  • 메뉴·식당 기록하면 다음 차례로
  • 이력 목록: 날짜, 고른 사람, 메뉴, 식당, 한줄평
데이터 구조 예시 
devotion/{팀코드}                    members, nextIndex, skipped
devotion/{팀코드}/days/{2026-11-02}  passage, leader, withDirector, sharing, ...
lunch/{팀코드}                       members, nextIndex, skipped
lunch/{팀코드}/logs/{자동ID}         date, picker, menu, place, rating
진행 순서
  1. 플랜 모드(Shift+Tab)로 계획부터 받기. "level-up 앱의 Firebase 연결 방식을 참고해줘"라고 알려주면 빠릅니다
  2. Firebase 없이 화면부터 만들고 휴대폰 폭에서 확인
  3. Firestore에 연결해 팀 코드로 함께 보기
  4. PR로 올리고 다른 조 리뷰 받기
관리자용: Firestore 보안 규칙 추가

Firebase 콘솔 → Firestore → 규칙에 아래를 추가해야 새 경로에 저장됩니다. 기존 규칙(가계부·여행 지도·레벨업)은 그대로 두세요.

// 기존 match /databases/{database}/documents { ... } 안에 추가
match /devotion/{team}/{rest=**} {
  allow read, write: if team.size() >= 6;
}
match /lunch/{team}/{rest=**} {
  allow read, write: if team.size() >= 6;
}

교육용 최소 규칙입니다. 팀 코드를 아는 사람은 누구나 읽고 쓸 수 있으니 6자 이상, 추측하기 어렵게 정하세요.

잘 시키는 법

클로드는 똑똑하지만 우리 팀 사정은 모릅니다. 사람에게 일을 맡기듯 배경을 알려주세요.

좋은 요청의 네 가지 재료
  • 배경 누가, 왜 쓰는 결과물인지
  • 목표 최종적으로 무엇이 나와야 하는지
  • 제약 분량, 말투, 쓰면 안 되는 것
  • 형식 표, 목록, HTML, 엑셀 붙여넣기용 등
클로드 코드에서 특히
  • 큰 작업은 플랜 모드(Shift+Tab)로 계획부터 보고 승인
  • 한 번에 하나씩. 작게 나눠서 시키면 실수가 줄어듭니다
  • "다 하면 휴대폰 폭에서 확인해줘"처럼 검증 방법을 같이 주기
  • 방향이 틀어지면 Esc로 멈추고 바로잡기
아쉬운 요청 
보고서 써줘
좋은 요청 
첨부한 9월 매출 데이터로 팀장 보고용 요약을 써줘.
- 목적: 다음 주 예산 회의 자료
- 분량: A4 반 페이지, 핵심 수치 3개 먼저
- 형식: 제목 + 요약 3줄 + 표 1개
- 전월 대비 변화는 % 로 표시
결과는 항상 확인하기
  • AI는 그럴듯하게 틀릴 수 있습니다(할루시네이션). 숫자·인용·법률 내용은 원본과 대조하세요.
  • 대화가 너무 길어지면 앞부분을 잊기 시작합니다. 주제가 바뀌면 새 대화를 여세요.

입력하는 일언제 쓰나
